# 策略回测引擎 设计文档（第一阶段）

- 日期：2026-08-01
- 状态：设计确认中
- 范围：量化能力四阶段路线（①回测引擎 → ②多因子选股 → ③AI+量化结合 → ④信号自动化）中的**第一阶段：策略回测引擎**

---

## 1. 背景与目标

TradingAgents-CN 现状是一套**多智能体 AI 分析引擎**（分析师→研究员辩论→交易员→风控，产出研究报告与买/卖/持有信号），已具备：tushare 数据、minimax LLM、技术指标计算、股票筛选、模拟盘。

缺口：**无法回答"一套买卖逻辑在历史上到底赚不赚钱"**。回测引擎补齐这一核心缺口，并作为后续因子选股、AI+量化、信号自动化的公共地基。

**第一阶段目标**：做一个**单股、逐日回放**的通用回测引擎，用户在 Web 上用"条件积木"定义买卖策略，回测历史行情，得到净值曲线、绩效指标、交易明细，并与"买入持有"基准对比。

## 2. 范围

**做（第一版）**
- 单股回测（A股）
- 逐日回放（事件驱动）内核
- 条件积木式策略（技术指标规则，AND/OR 组合）
- 固定份数分批仓位
- A股撮合规则：T+1、停牌顺延、涨跌停限制、交易成本
- 绩效评价 + 买入持有基准
- 接入现有 Web（新增"策略回测"页，异步任务）
- 数据读本地 MongoDB 历史库（前复权价）

**不做（留后续阶段）**
- 多股组合/资金分配/再平衡（第一阶段只单股）
- AI 多智能体信号作为策略源（②③阶段接入，但**本期预留通用信号接口**）
- 分批的高级玩法（每规则自带仓位%、目标仓位档）
- 多因子选股（第二阶段）
- 实盘/自动下单（明确不做，守住"研究/回测"边界）

## 3. 整体架构

分两层，沿用项目现有分层（开源引擎层 + 专有 Web 层）。

### A. 引擎层（开源，新增 `tradingagents/backtest/`）——纯 Python，可独立测试

| 模块 | 职责 |
|---|---|
| `data_feed.py` | 从 MongoDB `stock_daily_quotes` 读**前复权**日线 + 交易日历 + 停牌，吐出干净的逐日行情序列。经 `historical_data_service` |
| `strategy.py` | 条件积木 → "每天该买/卖/空仓"的决定。定义**通用信号接口** `SignalSource`，未来 AI 信号源实现同接口即可接入 |
| `engine.py` | 逐日回放内核：遍历交易日→取当日可用数据→问策略要动作→交撮合→更新账户→记净值 |
| `broker.py` | 撮合与账户：按 A股规则成交（T+1、停牌顺延、涨跌停、成本），管现金/持仓 |
| `metrics.py` | 绩效评价：总收益、年化、最大回撤、夏普、胜率、盈亏比、交易次数 + 净值曲线 |
| `result.py` | 回测结果对象：净值曲线 + 交易明细 + 指标，可序列化给 API |

### B. Web 层（专有，接入现有系统）

| 模块 | 职责 |
|---|---|
| `app/routers/backtest.py` | `POST /api/backtest/run`（股票、区间、策略配置、成本/资金参数）→ 异步任务 → 结果。复用现有 Tasks/Queue |
| `app/services/backtest_service.py` | 薄层：调引擎、存/取结果 |
| `frontend/src/views/Backtest/` | "策略回测"页：选股票+区间+初始资金+条件积木编辑器 → 跑 → 净值曲线图 + 指标卡 + 交易明细表 |

### 数据流

```
页面配策略 ──POST──▶ backtest_service ──▶ engine 逐日回放
                                              │每交易日:
   data_feed(MongoDB 前复权+日历+停牌) ───────┤ 1. 取当日可用行情
                                              │ 2. strategy 给动作(加/减/不动)
                                              │ 3. broker 按A股规则撮合、扣成本
                                              │ 4. 记当日净值
                                              ▼
   净值曲线+交易明细+绩效指标 ◀──result──── metrics 汇总
        │
        ▼ 前端画:净值曲线图(策略 vs 买入持有) · 指标卡 · 交易明细表
```

**设计好处**：引擎层完全独立、可脱离 Web 单测（甚至 Jupyter 直接用）；Web 层是薄壳；后续接 AI 信号只需在 `strategy.py` 加一个实现 `SignalSource` 的类，引擎与页面几乎不动。

## 4. 数据层

**数据源已存在，直接复用，不新建。**

- 存储：MongoDB（容器 `tradingagents-mongodb`，库 `tradingagents`）
- 历史日线表：`stock_daily_quotes`（现有 32.9 万条、55 股、1997 至今，source=tushare）
- 服务入口：`historical_data_service`（`get_historical_data` / `get_latest_date` / `save_historical_data`）
- 字段：`open/high/low/close/pre_close/volume/amount/pct_chg` 等

**复权（关键）**：库中 `close` 为原始价。回测必须用前复权价，否则除权除息日收益严重失真。

- 方案（已定）：**同步时额外存一份前复权价**。
- 落地：改数据同步 worker（`app/worker/tushare_sync_service.py` / `multi_period_sync_service.py`），用 tushare 前复权（`pro_bar adj='qfq'` 或 `daily`+`adj_factor` 计算），在 `stock_daily_quotes` 增加复权价字段（如 `open_qfq/high_qfq/low_qfq/close_qfq`），回灌历史。
- 回测 `data_feed` 读复权价字段。

**要堵的坑**：
1. 前复权价（上）
2. 交易日历 + 停牌顺延（tushare `trade_cal` / `suspend`）
3. 缓存/查库（回测只读库，天然离线、不打 tushare 限频）
4. 前视偏差：回测到第 T 日只能用"T 日收盘后已知"的数据，成交发生在 T+1

**第 0 步（数据准备，前置）**：
1. 扩展同步 worker 存前复权价并回灌历史
2. 同步 ST 历史状态（tushare `namechange`）入库，供精确涨跌停按日判定 ST
3. 确保待回测股票在同步清单内

## 5. 策略层（条件积木）

一条规则 = `[指标] [比较] [值 / 另一指标]`，多条用 AND/OR 拼成"买入条件组"和"卖出条件组"。

- 支持指标（第一版，复用 `tradingagents/tools/analysis/indicators.py`）：MA/EMA、MACD（DIF/DEA/柱，金叉/死叉）、RSI、BOLL（上/中/下轨）、收盘价、成交量
- 比较符：`>`、`<`、`上穿(金叉)`、`下穿(死叉)`
- 求值：引擎每交易日算出各指标当日值，代入条件组求布尔
- 通用信号接口 `SignalSource`：输入=截至当日的行情/指标，输出=当日动作枚举（加仓 / 减仓 / 不动）。条件积木是其第一个实现；AI 信号源为后续实现

**示例**
- 买入 = `MA5 上穿 MA20` AND `RSI14 < 70`
- 卖出 = `收盘价 跌破 MA20` OR `RSI14 > 80`

## 6. 仓位模型（固定份数分批）

- 把总资金分成 **N 档**（N 与每档比例可配，默认 3 档、每档约 1/3）
- **买入信号**：若未满仓，买入一档（≈ 总资金 1/N，用当前可用现金按手 100 股取整），已满仓则忽略
- **卖出信号（减仓模式，配置化）**：
  - `reduce_one`（默认）：减一档，卖出建仓时每档对应股数
  - `clear_all`：卖出信号即全部清仓
- 同一交易日买入条件组为真只加一档（布尔信号，不叠加）
- 状态在 0 ~ N 档之间移动

**仓位参数（全部配置化）**：份数 N、每档比例、减仓模式（reduce_one / clear_all）。

## 7. 撮合与 A股规则

| 项 | 默认 / 规则 | 配置化 |
|---|---|---|
| 成交时点 | 信号在 T 日收盘后产生 → **T+1 开盘价**成交 | 否 |
| T+1 | 当日买入不可当日卖出 | 否 |
| 停牌 | 停牌日不成交，信号顺延到下一交易日 | 否 |
| 涨跌停 | **精确处理**（按板块+ST 判定，见 §7.1） | 否 |
| 佣金 | 双边万 2.5，最低 5 元 | **是** |
| 印花税 | 卖出千 1 | **是** |
| 过户费 | 万 0.1 | **是** |
| 初始资金 | 默认 10 万 | **是** |
| 份数 N / 每档比例 | 默认 3 档 | **是** |
| 减仓模式 | reduce_one（减一档）/ clear_all（全清），默认 reduce_one | **是** |

成本与资金参数由 API/页面传入，引擎不写死。

### 7.1 精确涨跌停规则

**涨跌幅（按板块，注册制后）**

| 板块 / 代码前缀 | 普通 | ST/*ST |
|---|---|---|
| 主板（沪 60x、深 000/001） | ±10% | ±5% |
| 创业板（300） | ±20% | ±20% |
| 科创板（688） | ±20% | ±20% |
| 北交所（8xx / 92x） | ±30% | ±30% |

（注册制板块 ST 不改变涨跌幅，仅主板 ST 为 ±5%。）

**涨跌停价**：`涨停价 = round(pre_close × (1 + pct), 2)`；`跌停价 = round(pre_close × (1 - pct), 2)`。`pre_close` 库中已有。

**成交可行性判定（T+1 开盘价成交）**
- 买入：若 `open ≥ 涨停价`（开盘即封涨停）→ 当日无法买入，信号顺延到下一交易日
- 卖出：若 `open ≤ 跌停价`（开盘即封跌停）→ 当日无法卖出，信号顺延
- 可选加强：若当日 `high == low ==` 涨/跌停价（一字板全天封死），则该方向全天不可成交

**数据依赖（并入第 0 步数据准备）**
- 板块：由股票代码前缀识别，复用 `tradingagents/utils/stock_utils.py` 的 `StockUtils`
- ST 历史状态：需**按回测日期**判定某股当日是否为 ST（ST 状态随时间变化）。数据源用 tushare `namechange`（曾用名/ST 标记的时间区间），同步入库供回测查询
- `pre_close`：`stock_daily_quotes` 已有

## 8. 绩效评价

- **净值曲线**：每日总资产 / 初始资金
- **指标**：总收益率、年化收益率、最大回撤、夏普比率、胜率、盈亏比、交易次数、平均持仓天数
- **基准对比**：同期"买入持有不动"净值曲线，判断策略是否跑赢躺平
- **交易明细**：每笔买/卖的日期、成交价、数量、手续费、盈亏

## 9. Web 接入

- **接口**：`POST /api/backtest/run`，body = {symbol, start_date, end_date, initial_capital, cost_params, position_params, buy_rules, sell_rules}；异步任务返回 task_id，完成后取结果
- **异步**：复用现有 Tasks/Queue，避免长回测阻塞请求；前端轮询/SSE 显示进度
- **页面** `frontend/src/views/Backtest/`：
  - 输入区：股票选择（复用现有组件）、日期区间、初始资金、成本参数、份数、条件积木编辑器（买入组/卖出组，可加减规则行，指标+比较+值，AND/OR 切换）
  - 结果区：净值曲线图（策略 vs 买入持有）、绩效指标卡、交易明细表
  - 复用：现有股票选择组件、Tasks/Queue、前端图表库

## 10. 错误处理

- 数据缺失（区间内无数据/股票未同步）：明确提示"请先同步该股票历史数据"，不静默返回空
- 区间内全程停牌/无有效交易日：返回可读错误
- 策略条件非法（指标参数越界、空条件组）：接口层校验并返回具体原因
- 复权字段缺失：`data_feed` 检测到无复权价则报错并提示补数据，绝不用原始价静默回测
- 资金不足买不起一手：跳过该次买入并在交易日志记录

## 11. 测试策略

- 引擎层纯 Python，单元测试为主：
  - `data_feed`：给定库数据，正确产出复权序列、正确处理停牌/日历
  - `strategy`：条件积木求值（金叉/死叉、AND/OR、边界）
  - `broker`：T+1 限制、成本计算、分批加减档、涨跌停不成交
  - `metrics`：已知净值序列的指标计算（回撤/夏普/胜率）对拍手算结果
- 端到端：构造小段已知行情，跑一条简单策略（如双均线），核对交易点与净值
- 基准：买入持有净值 = 复权价首末之比，作为交叉验证
